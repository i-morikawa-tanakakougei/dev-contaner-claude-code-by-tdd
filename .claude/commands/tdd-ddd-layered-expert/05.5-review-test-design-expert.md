- **Completion**: All tests appropriately fail, clear expression of business intent, demonstration of implementation guidance functionality
- **Escalation**: Detection of test success state, uncovered critical scenarios, discovery of test quality defects

## GitHub Issue Integration

#### Issue Comment Retrieval and Analysis
```bash
# Load GitHub issue context for test coverage validation
if [[ -n "$ISSUE_NUMBERS" ]]; then
    for ISSUE_NUM in $ISSUE_NUMBERS; do
        echo "Retrieving GitHub issue #$ISSUE_NUM with comments for test design review..."
        
        # Get issue details with comments
        ISSUE_DATA=$(gh issue view $ISSUE_NUM --json title,body,comments,updatedAt,createdAt,labels,assignees)
        
        # Extract and prioritize recent comments
        RECENT_COMMENTS=$(echo "$ISSUE_DATA" | jq -r '.comments | sort_by(.createdAt) | reverse | .[0:5]')
        
        COMMENT_COUNT=$(echo "$ISSUE_DATA" | jq '.comments | length')
        echo "Found $COMMENT_COUNT comments on issue #$ISSUE_NUM"
        echo "Prioritizing latest 5 comments for test design validation"
        
        # Check for test design feedback through comments
        if [[ $COMMENT_COUNT -gt 0 ]]; then
            echo "Analyzing comment timeline for test design feedback..."
            # Recent comments take precedence for test validation
            LATEST_COMMENT_DATE=$(echo "$RECENT_COMMENTS" | jq -r '.[0].createdAt // empty')
            if [[ -n "$LATEST_COMMENT_DATE" ]]; then
                echo "Latest test design update: $LATEST_COMMENT_DATE"
            fi
            
            # Extract test design related comments
            echo "Extracting test design validation context..."
            echo "$RECENT_COMMENTS" | jq -r '.[] | select(.body | contains("test") or contains("coverage") or contains("scenario") or contains("validation") or contains("TDD")) | .body' | head -3
        fi
    done
fi
```

## 🚀 Expert Execution Flow

### Phase 1: TDD RED Phase Verification
**Execute as expert:**
1. **Execute All Tests and Confirm Initial RED State**
   ```bash
   # Execute all tests to verify initial RED phase (all tests should fail)
   echo "Executing test suite to validate initial RED phase..."
   uv run --frozen pytest tests/ -v --tb=short
   
   # Expected: All tests should fail with appropriate reasons
   # Valid failure reasons: ImportError, NotImplementedError, AttributeError (missing implementation)
   # Invalid: Tests passing (indicates implementation exists) or logical errors
   ```

2. **Validate Staged Implementation Testability**
   ```bash
   # Verify tests can be executed independently by implementation layer
   echo "Validating layered test execution capability..."
   
   # Test domain layer readiness (should be immediately testable after domain implementation)
   echo "Testing domain-only test execution patterns..."
   uv run --frozen pytest tests/ -k "domain" -v --collect-only
   
   # Test use case layer readiness (should be testable after domain + use case implementation)
   echo "Testing use case test execution patterns..."
   uv run --frozen pytest tests/ -k "use_case or usecase" -v --collect-only
   
   # Test infrastructure layer readiness
   echo "Testing infrastructure test execution patterns..."
   uv run --frozen pytest tests/ -k "infra or repository" -v --collect-only
   
   # Test presentation layer readiness
   echo "Testing presentation test execution patterns..."
   uv run --frozen pytest tests/ -k "presentation or api or cli" -v --collect-only
   ```

3. **Verify Staged GREEN Transition Design**
   ```bash
   # Validate that tests are designed for proper staged GREEN transitions
   echo "Validating staged GREEN transition design..."
   
   # Check for appropriate test categorization and dependencies
   # Domain tests should not depend on infrastructure
   # Use case tests should only depend on domain
   # Infrastructure tests should mock external dependencies
   # Presentation tests should have proper integration points
   
   # Expected progression:
   # Step 1: All RED (initial state)
   # Step 2: Domain tests GREEN, others RED
   # Step 3: Domain + Use Case tests GREEN, others RED  
   # Step 4: Domain + Use Case + Infrastructure tests GREEN, Presentation RED
   # Step 5: All tests GREEN (final state)
   ```
   
4. **Evaluate Validity of Test Failure Reasons**
   - Verification Points: Appropriate failures due to ImportError (unimplemented modules), NotImplementedError (explicit non-implementation)
   - Judgment Criteria: Failures due to missing implementation, not logical errors or test bugs
   - Layer Isolation: Domain tests should not fail due to infrastructure concerns

### Phase 2: Given-When-Then Scenario Coverage Analysis
**Evaluate as expert:**
1. **Scenario-Test Correspondence Verification**
   ```
   Coverage Analysis Items:
   - Scenario Completeness: Confirm existence of tests for all Given-When-Then scenarios
   - Acceptance Criteria Correspondence: Confirm explicit tests for each acceptance criterion
   - Edge Case Coverage: Confirm test coverage for boundary values and exception conditions
   ```
   
2. **Business Logic Test Quality Evaluation**
   ```
   Test Quality Evaluation Criteria:
   - Business Intent Clarity: Understandability of business requirements from test names and structure
   - Test Independence: Independent executability of each test with no side effects
   - Data Quality: Reality, representativeness, and maintainability of test data
   ```

### Phase 3: Test Structure and Maintainability Quality Evaluation
**Execute as expert:**
1. **Test Architecture Conformity Verification**
   - Action: Verify test structure corresponding to layered architecture (unit/integration/e2e separation)
   - Expected Result: Test implementation at appropriate abstraction levels, validation of mock strategy appropriateness
   
2. **Test Maintainability and Extensibility Evaluation**
   - Action: Evaluate test code quality (naming, structure, duplication, dependencies)
   - Expected Result: Ensure long-term maintainability, ease of adaptation to requirement changes

### Phase 4: Staged GREEN Transition Validation
**Execute as expert:**
1. **Layer Isolation and Dependency Analysis**
   ```bash
   # Analyze test dependencies to ensure proper layer isolation
   echo "Analyzing test layer dependencies for staged implementation..."
   
   # Check domain test isolation (should not import from infrastructure/presentation)
   grep -r "from.*infrastructure\|from.*presentation" tests/ --include="*domain*" && echo "❌ Domain tests have invalid dependencies" || echo "✅ Domain tests properly isolated"
   
   # Check use case test dependencies (should only depend on domain)
   grep -r "from.*infrastructure\|from.*presentation" tests/ --include="*use_case*" && echo "❌ Use case tests have invalid dependencies" || echo "✅ Use case tests properly isolated"
   
   # Verify mock usage for external dependencies in infrastructure tests
   grep -r "@mock\|Mock\|patch" tests/ --include="*infra*" || echo "⚠️ Infrastructure tests may need mocking for external dependencies"
   ```

2. **Staged Execution Simulation**
   ```bash
   # Simulate the staged GREEN transition process
   echo "Simulating staged GREEN transition..."
   
   # Document expected test execution patterns for each implementation phase
   echo "Phase 6 (Domain Implementation): Domain tests should pass"
   echo "  Command: uv run --frozen pytest tests/ -k 'domain' -v"
   echo "  Expected: Domain tests GREEN, others RED"
   echo ""
   
   echo "Phase 7 (Use Case Implementation): Domain + Use Case tests should pass"
   echo "  Command: uv run --frozen pytest tests/ -k 'domain or use_case' -v"
   echo "  Expected: Domain + Use Case tests GREEN, others RED"
   echo ""
   
   echo "Phase 8 (Infrastructure Implementation): Domain + Use Case + Infrastructure tests should pass"
   echo "  Command: uv run --frozen pytest tests/ -k 'domain or use_case or infra or repository' -v"
   echo "  Expected: Domain + Use Case + Infrastructure tests GREEN, Presentation RED"
   echo ""
   
   echo "Phase 9 (Presentation Implementation): All tests should pass"
   echo "  Command: uv run --frozen pytest tests/ -v"
   echo "  Expected: All tests GREEN"
   ```

3. **Test Categorization Verification**
   ```bash
   # Verify tests are properly categorized for staged execution
   echo "Verifying test categorization for staged execution..."
   
   # Check for proper test naming patterns
   find tests/ -name "*.py" -type f | while read test_file; do
       echo "Analyzing test file: $test_file"
       
       # Check if tests are properly categorized by layer
       if grep -q "class.*Domain\|def test.*domain" "$test_file"; then
           echo "  ✅ Contains domain tests"
       fi
       
       if grep -q "class.*UseCase\|def test.*use_case\|def test.*usecase" "$test_file"; then
           echo "  ✅ Contains use case tests"
       fi
       
       if grep -q "class.*Infra\|class.*Repository\|def test.*infra\|def test.*repository" "$test_file"; then
           echo "  ✅ Contains infrastructure tests"
       fi
       
       if grep -q "class.*Presentation\|class.*API\|class.*CLI\|def test.*presentation\|def test.*api\|def test.*cli" "$test_file"; then
           echo "  ✅ Contains presentation tests"
       fi
   done
   ```

1. **Test Success State Detection**: Remove implementation code, review test implementation, re-establish RED state

4. **Incorrect Test Categorization**: Re-organize tests by proper layer classification for staged execution
5. **Mock Strategy Issues**: Add proper mocking for external dependencies in infrastructure tests
