## 🚀 Expert Execution Flow

### Phase 1: TDD RED Phase Verification
**Execute as expert:**
1. **Execute All Tests and Confirm Failure State**
   ```bash
   # Execute all tests to verify RED phase
   echo "Executing test suite to validate RED phase..."
   uv run --frozen pytest tests/ -v --tb=short
   
   # Expected: All tests should fail with appropriate reasons
   # Valid failure reasons: ImportError, NotImplementedError, AttributeError (missing implementation)
   # Invalid: Tests passing (indicates implementation exists) or logical errors
   ```
   
2. **Evaluate Validity of Test Failure Reasons**
   - Verification Points: Appropriate failures due to ImportError (unimplemented modules), NotImplementedError (explicit non-implementation)
   - Judgment Criteria: Failures due to missing implementation, not logical errors or test bugs

### Phase 2: Given-When-Then Scenario Coverage Analysis
**Evaluate as expert:**
1. **Scenario-Test Correspondence Verification**
   ```
   Coverage Analysis Items:
   - Scenario Completeness: Confirm existence of tests for all Given-When-Then scenarios
   - Acceptance Criteria Correspondence: Confirm explicit tests for each acceptance criterion
   - Edge Case Coverage: Confirm test coverage for boundary values and exception conditions
   ```
   
2. **Business Logic Test Quality Evaluation**
   ```
   Test Quality Evaluation Criteria:
   - Business Intent Clarity: Understandability of business requirements from test names and structure
   - Test Independence: Independent executability of each test with no side effects
   - Data Quality: Reality, representativeness, and maintainability of test data
   ```

### Phase 3: Test Structure and Maintainability Quality Evaluation
**Execute as expert:**
1. **Test Architecture Conformity Verification**
   - Action: Verify test structure corresponding to layered architecture (unit/integration/e2e separation)
   - Expected Result: Test implementation at appropriate abstraction levels, validation of mock strategy appropriateness
   
2. **Test Maintainability and Extensibility Evaluation**
   - Action: Evaluate test code quality (naming, structure, duplication, dependencies)
   - Expected Result: Ensure long-term maintainability, ease of adaptation to requirement changes
