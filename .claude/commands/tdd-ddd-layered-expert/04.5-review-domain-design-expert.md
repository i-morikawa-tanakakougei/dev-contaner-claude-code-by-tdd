## 🚀 専門家実行フロー

### Phase 1: DDD設計原則準拠性評価
**専門家として以下を分析:**
1. **エンティティ設計品質評価**
   - 確認ポイント: アイデンティティ定義の明確性、ライフサイクル管理の適切性、不変条件設定
   - 判断基準: 一意性保証機能、状態変更制御、ビジネスルール内包度
   
2. **値オブジェクト設計妥当性確認**
   - 確認ポイント: 不変性保証、等価性実装、検証ロジック内蔵、合成可能性
   - 判断基準: 副作用なし設計、型安全性確保、ドメイン概念の適切な抽象化

### Phase 2: 集約境界・参照関係検証
**専門家として以下を評価:**
1. **集約境界設計の妥当性**
   ```
   集約境界評価基準:
   - 一貫性境界: ビジネス不変条件を保護する境界設定
   - トランザクション境界: データ整合性保証範囲の適切性
   - 集約ルート: 外部アクセス制御と内部整合性管理
   ```
   
2. **集約間参照関係の設計品質**
   ```
   参照関係評価項目:
   - 直接参照回避: 文字列IDやValue Object経由での参照設計
   - 結合度制御: 集約間の疎結合実現状況
   - 協調メカニズム: ドメインサービスやイベント活用状況
   ```

### Phase 3: ビジネスルール配置・アーキテクチャ整合性確認
**専門家として以下を実行:**
1. **ビジネスロジック配置の適切性確認**
   - アクション: ビジネスルールの適切な配置（エンティティ内、ドメインサービス内）確認
   - 期待結果: アプリケーション層・インフラ層への漏洩防止、ドメイン純粋性維持
   
2. **既存ドメインモデルとの整合性評価**
   - アクション: 共通語彙、設計パターン、アーキテクチャ原則の一貫性確認
   - 期待結果: システム全体のドメインモデル統合性と発展可能性確保
