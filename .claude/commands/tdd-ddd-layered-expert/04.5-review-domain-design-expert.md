## GitHub Issue Integration

#### Issue Comment Retrieval and Analysis
```bash
# Load GitHub issue context for design alignment
if [[ -n "$ISSUE_NUMBERS" ]]; then
    for ISSUE_NUM in $ISSUE_NUMBERS; do
        echo "Retrieving GitHub issue #$ISSUE_NUM with comments for domain design review..."
        
        # Get issue details with comments
        ISSUE_DATA=$(gh issue view $ISSUE_NUM --json title,body,comments,updatedAt,createdAt,labels,assignees)
        
        # Extract and prioritize recent comments
        RECENT_COMMENTS=$(echo "$ISSUE_DATA" | jq -r '.comments | sort_by(.createdAt) | reverse | .[0:5]')
        
        COMMENT_COUNT=$(echo "$ISSUE_DATA" | jq '.comments | length')
        echo "Found $COMMENT_COUNT comments on issue #$ISSUE_NUM"
        echo "Prioritizing latest 5 comments for domain design validation"
        
        # Check for domain design feedback through comments
        if [[ $COMMENT_COUNT -gt 0 ]]; then
            echo "Analyzing comment timeline for domain design feedback..."
            # Recent comments take precedence for design validation
            LATEST_COMMENT_DATE=$(echo "$RECENT_COMMENTS" | jq -r '.[0].createdAt // empty')
            if [[ -n "$LATEST_COMMENT_DATE" ]]; then
                echo "Latest domain design update: $LATEST_COMMENT_DATE"
            fi
            
            # Extract domain design related comments
            echo "Extracting domain design validation context..."
            echo "$RECENT_COMMENTS" | jq -r '.[] | select(.body | contains("domain") or contains("design") or contains("entity") or contains("aggregate") or contains("validation")) | .body' | head -3
        fi
    done
fi
```

## 🚀 Expert Execution Flow

### Phase 1: DDD Design Principle Compliance Assessment
**As an expert, analyze the following:**
1. **Entity Design Quality Evaluation**
   - Verification Points: Identity definition clarity, lifecycle management appropriateness, invariant condition setting
   - Judgment Criteria: Uniqueness guarantee functionality, state change control, business rule encapsulation degree
   
2. **Value Object Design Validity Confirmation**
   - Verification Points: Immutability guarantee, equality implementation, built-in validation logic, composability
   - Judgment Criteria: Side-effect-free design, type safety assurance, appropriate abstraction of domain concepts

### Phase 2: Aggregate Boundary and Reference Relationship Verification
**As an expert, evaluate the following:**
1. **Aggregate Boundary Design Validity**
   ```
   Aggregate Boundary Evaluation Criteria:
   - Consistency Boundary: Boundary setting that protects business invariant conditions
   - Transaction Boundary: Appropriateness of data integrity guarantee scope
   - Aggregate Root: External access control and internal consistency management
   ```
   
2. **Inter-Aggregate Reference Relationship Design Quality**
   ```
   Reference Relationship Evaluation Items:
   - Direct Reference Avoidance: Reference design via string IDs or Value Objects
   - Coupling Control: Loose coupling realization status between aggregates
   - Collaboration Mechanism: Domain service and event utilization status
   ```

### Phase 3: Business Rule Placement and Architecture Consistency Confirmation
**As an expert, execute the following:**
1. **Business Logic Placement Appropriateness Confirmation**
   - Action: Confirm appropriate placement of business rules (within entities, within domain services)
   - Expected Result: Prevention of leakage to application/infrastructure layers, domain purity maintenance
   
2. **Consistency Evaluation with Existing Domain Models**
   - Action: Confirm consistency of common vocabulary, design patterns, architectural principles
   - Expected Result: System-wide domain model integration and evolution capability assurance
