## 🚀 専門家実行フロー

### Phase 1: スプリント文書構造分析
**専門家として以下を分析:**
1. **スプリント目標・範囲評価**
   - 確認ポイント: 明確な成功基準設定、測定可能なアウトカム定義、スコープ境界の明示
   - 判断基準: SMART原則適用、ビジネス価値明確化、完了判定基準の客観性
   
2. **選択シナリオの優先度妥当性**
   - 確認ポイント: コアシナリオ80%ルール遵守、ビジネス価値順での優先度設定
   - 判断基準: ROI分析結果、リスク・インパクト評価、ステークホルダー価値認識

### Phase 2: 容量計画・実行可能性評価
**専門家として以下を評価:**
1. **チーム容量とワークロード適合性**
   ```
   容量分析項目:
   - 利用可能工数: チームメンバー稼働率、休暇・会議等控除後実工数
   - 見積もり精度: 過去実績ベースの見積もり妥当性、バッファ設定適切性
   - スキル適合性: 必要スキルとチーム保有スキルのマッチング状況
   ```
   
2. **依存関係・リスク評価**
   ```
   リスク評価項目:
   - 外部依存: 他チーム・システム・承認プロセス等への依存度
   - 技術リスク: 新技術・未経験領域・複雑性によるリスク
   - スケジュールリスク: 固定期限・イベント・マイルストーンとの整合性
   ```

### Phase 3: GitHub Issue戦略検証と最適化推奨
**専門家として以下を実行:**
1. **Issue構造・戦略の妥当性確認**
   - アクション: 1-scenario-1-issue戦略の適用状況、粒度の適切性確認
   - 期待結果: 効率的な並行作業とトレーサビリティの両立確認
   
2. **受け入れ基準・完了定義の品質評価**
   - アクション: Given-When-Then形式での受け入れ基準完成度評価
   - 期待結果: 客観的な完了判定基準設定と品質保証機能確認
