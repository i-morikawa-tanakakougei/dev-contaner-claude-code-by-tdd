## Common Errors and Solutions

### ❌ Error Case 1: DDD aggregate boundary violations
**Cause**: Direct entity references across aggregate boundaries (like Trade→Position)  
**Solution**: 
```bash
# Fix aggregate coupling
- Replace direct object references with string ID references
- Use coordination aggregates for cross-boundary consistency
- Implement domain services for cross-aggregate operations
# Then re-review
/review-domain-design <issue-number>
```

### ❌ Error Case 2: Domain model design document not found
**Cause**: Domain design review attempted before design creation  
**Solution**: 
```bash
# Create domain design first
/domain-modeling <issue-number>
# Then proceed with review
/review-domain-design <issue-number>
```

### ❌ Error Case 3: Inconsistency with existing domain models
**Cause**: New design conflicts with established domain patterns or shared foundation  
**Solution**: 
- Analyze existing domain models for consistency
- Align with shared value objects and patterns
- Consider refactoring existing models if necessary
- Update design to maintain architectural coherence

## 📋 **DOMAIN DESIGN REVIEW TASK CHECKLIST**

**Use this checklist for comprehensive domain design quality assessment:**

### 🔴 Required Tasks

#### **📖 Design Document Analysis**
- [ ] **Verify design document exists**: Confirm `docs/domain/issue-X-Y-domain-model.md` is available
- [ ] **Analyze domain concepts**: Review entities, value objects, and aggregates
- [ ] **Check business rules placement**: Verify invariants and constraints are properly located
- [ ] **Validate ubiquitous language consistency**: Ensure terminology aligns with project standards

#### **🏗️ DDD Compliance Validation**
- [ ] **Verify aggregate boundaries**: Check for proper aggregate root identification and boundaries
- [ ] **Validate entity design**: Ensure entities have identity, lifecycle, and appropriate behavior
- [ ] **Check value object design**: Verify immutability, validation, and equality implementation
- [ ] **Review aggregate references**: Confirm no direct object references across aggregate boundaries

#### **🔗 Integration Analysis**
- [ ] **Check existing domain consistency**: Verify alignment with established domain models
- [ ] **Validate shared foundation usage**: Confirm proper use of common value objects and patterns
- [ ] **Review architectural coherence**: Ensure design maintains overall system architecture

### 🟡 Recommended Tasks

#### **🎯 Business Logic Assessment**
- [ ] **Validate business rule encapsulation**: Check that business logic is properly encapsulated in domain objects
- [ ] **Review domain services design**: Assess complex business logic that spans multiple entities
- [ ] **Check invariant definition**: Verify business invariants are clearly defined and enforceable
- [ ] **Assess calculation logic placement**: Ensure business calculations are in appropriate domain objects

#### **📊 Design Quality Evaluation**
- [ ] **Review entity lifecycle management**: Check entity creation, modification, and deletion patterns
- [ ] **Validate repository interface design**: Assess data access abstraction quality
- [ ] **Check domain event design**: Review event definitions for side effects and integration
- [ ] **Assess extensibility**: Evaluate design flexibility for future requirements

### 🟢 Optional Tasks

#### **🔍 Advanced Design Analysis**
- [ ] **Performance consideration review**: Identify potential performance issues in design
- [ ] **Validate transaction boundaries**: Ensure appropriate transaction scope definition
- [ ] **Review error handling strategy**: Check domain-level error handling and validation
- [ ] **Assess testability**: Evaluate how easily the design can be tested

#### **💰 Domain-Specific Considerations (例: 円建て対応)**
- [ ] **Validate currency handling**: Check proper currency and precision management
- [ ] **Review calculation accuracy**: Ensure financial calculations maintain required precision
- [ ] **Check regulatory compliance**: Verify domain rules align with business regulations
- [ ] **Assess localization support**: Evaluate support for regional business requirements

#### **🔄 Design Evolution Assessment**
- [ ] **Check migration compatibility**: Assess compatibility with existing implementations
- [ ] **Review refactoring requirements**: Identify necessary changes to existing code
- [ ] **Validate backward compatibility**: Ensure design changes don't break existing functionality
- [ ] **Assess impact scope**: Evaluate the scope of changes required across the system

### **📝 Documentation and Communication**
- [ ] **Create design review report**: Generate comprehensive design assessment document
- [ ] **Document design decisions**: Record rationale for key design choices
- [ ] **List required modifications**: Identify specific changes needed before implementation
- [ ] **Generate approval status**: Provide clear go/no-go decision for TDD implementation

## Task Details

1. **Setup Safe Environment and Parse Arguments**:
   ```bash
   # 🔧 Load all safe operation functions
   source "$(dirname "${BASH_SOURCE[0]}")/_setup_safe_environment.sh" "04.5-review-domain-design" "$ARGUMENTS"
   
   # Design review expects at least one issue number
   if [[ ${#issue_numbers[@]} -eq 0 ]]; then
       echo "エラー: 少なくとも1つのイシュー番号を指定してください"
       show_usage_example "review-domain-design" "3" "単一イシューの設計レビュー"
       show_usage_example "review-domain-design" "3,7" "複数イシューの設計レビュー"
       show_usage_example "review-domain-design" "3 trading-execution" "イシュー + 機能名指定"
       exit 1
   fi
   
   # Extract issue list and feature name
   issue_list=$(IFS=-; echo "${issue_numbers[*]}")
   if [[ ${#other_args[@]} -gt 0 ]]; then
       feature_name="${other_args[0]}"
   else
       # Feature name will be extracted from existing design files
       feature_name=""
   fi
   
   echo "🔍 Issues: $(printf '#%s ' "${issue_numbers[@]}")のドメイン設計レビューを開始します"
   ```

2. **Validate Prerequisites and Locate Design Documents**:
   ```bash
   # 📋 Validate that domain design documents exist
   echo "📋 設計文書分析中..."
   
   missing_designs=()
   design_files=()
   
   for issue_num in "${issue_numbers[@]}"; do
       # Search for domain design document
       if [[ -n "$feature_name" ]]; then
           design_file="docs/domain/issue-${issue_num}-${feature_name}-domain-model.md"
       else
           # Find existing design file
           design_file=$(find docs/domain -name "issue-${issue_num}-*-domain-model.md" | head -1)
           if [[ -z "$design_file" ]]; then
               design_file="docs/domain/issue-${issue_num}-domain-model.md"
           fi
       fi
       
       if [[ -f "$design_file" ]]; then
           design_files+=("$design_file")
           echo "  📖 分析中: $design_file"
       else
           missing_designs+=("Issue #$issue_num")
       fi
   done
   
   # Check for missing designs
   if [[ ${#missing_designs[@]} -gt 0 ]]; then
       echo "❌ 以下のイシューの設計文書が見つかりません:"
       printf '  - %s\n' "${missing_designs[@]}"
       echo "💡 最初に以下のコマンドでドメイン設計を作成してください:"
       echo "   /domain-modeling ${issue_numbers[*]}"
       exit 1
   fi
   
   echo "✅ 設計文書確認完了: ${#design_files[@]} 個の設計を発見"
   ```

3. **Analyze Domain Design Documents**:
   ```bash
   # 🎯 Extract and analyze domain concepts
   echo "🎯 ドメイン概念分析中..."
   
   total_entities=0
   total_value_objects=0
   total_aggregates=0
   design_issues=()
   
   for design_file in "${design_files[@]}"; do
       # Count domain concepts
       entities=$(grep -c "^- \*\*.*Entity\*\*" "$design_file" 2>/dev/null || echo "0")
       value_objects=$(grep -c "^- \*\*.*Value.*Object\*\*\|^- \*\*.*値オブジェクト\*\*" "$design_file" 2>/dev/null || echo "0")
       aggregates=$(grep -c "^- \*\*.*Aggregate\*\*\|^- \*\*.*集約\*\*" "$design_file" 2>/dev/null || echo "0")
       
       total_entities=$((total_entities + entities))
       total_value_objects=$((total_value_objects + value_objects))
       total_aggregates=$((total_aggregates + aggregates))
       
       echo "  📊 $design_file: ${entities}個のエンティティ, ${value_objects}個の値オブジェクト, ${aggregates}個の集約"
   done
   
   echo "  🎯 ドメイン概念: ${total_entities}個のエンティティ, ${total_value_objects}個の値オブジェクト, ${total_aggregates}個の集約"
   ```

4. **DDD Compliance Analysis**:
   ```bash
   # 📊 Check DDD compliance
   echo "📊 DDD準拠性チェック中..."
   
   ddd_violations=()
   ddd_warnings=()
   
   # Check for aggregate boundary violations
   for design_file in "${design_files[@]}"; do
       # Look for direct entity references (common violation)
       if grep -q "直接参照\|direct reference\|entity.*\..*entity" "$design_file" 2>/dev/null; then
           ddd_violations+=("集約境界違反の可能性: $design_file")
       fi
       
       # Check for proper business rule placement
       if ! grep -q "ビジネスルール\|business rule\|invariant" "$design_file" 2>/dev/null; then
           ddd_warnings+=("ビジネスルール定義不足: $design_file")
       fi
       
       # Check for value object immutability mentions
       if ! grep -q "不変\|immutable\|readonly" "$design_file" 2>/dev/null; then
           ddd_warnings+=("値オブジェクト不変性の明記不足: $design_file")
       fi
   done
   
   # Report DDD compliance status
   if [[ ${#ddd_violations[@]} -eq 0 ]]; then
       echo "  ✅ 集約境界設計: 適切"
       echo "  ✅ エンティティ分類: 適切"
       echo "  ✅ 値オブジェクト設計: 適切"
       echo "  ✅ ビジネスルール配置: 適切"
   else
       echo "  ❌ DDD違反が検出されました:"
       printf '    ⚠️ %s\n' "${ddd_violations[@]}"
   fi
   
   if [[ ${#ddd_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ DDD改善推奨事項:"
       printf '    💡 %s\n' "${ddd_warnings[@]}"
   fi
   ```

5. **Integration and Consistency Analysis**:
   ```bash
   # 🔗 Check integration with existing domain models
   echo "🔗 既存ドメインとの整合性チェック中..."
   
   integration_issues=()
   
   # Check for consistency with shared foundation
   if [[ -d "src/domain/shared" ]]; then
       echo "  ✅ Issue #2共通基盤との互換性: 確認中"
       
       # Check if design mentions shared value objects
       shared_usage_count=0
       for design_file in "${design_files[@]}"; do
           if grep -q "Money\|Price\|Symbol\|AccountCurrency" "$design_file"; then
               shared_usage_count=$((shared_usage_count + 1))
           fi
       done
       
       if [[ $shared_usage_count -gt 0 ]]; then
           echo "  ✅ 共通基盤活用: ${shared_usage_count}個の設計で確認"
       else
           integration_issues+=("共通基盤の活用が不十分")
       fi
   fi
   
   # Check architectural consistency
   existing_designs=$(find docs/domain -name "*-domain-model.md" | wc -l)
   echo "  📊 既存設計との整合性: ${existing_designs}個の既存設計と比較"
   
   if [[ ${#integration_issues[@]} -eq 0 ]]; then
       echo "  ✅ 全体アーキテクチャ一貫性: 維持"
   else
       echo "  ⚠️ 統合課題:"
       printf '    💡 %s\n' "${integration_issues[@]}"
   fi
   ```

6. **Generate Review Report and Decision**:
   ```bash
   # 📝 Generate comprehensive review report
   echo "📝 設計レビューレポート作成中..."
   
   review_report="docs/reviews/domain-design-review-${issue_list}-$(date +%Y%m%d).md"
   mkdir -p "$(dirname "$review_report")"
   
   # Determine overall status
   if [[ ${#ddd_violations[@]} -eq 0 && ${#integration_issues[@]} -eq 0 ]]; then
       review_status="APPROVED"
       status_icon="✅"
       next_action="TDD実装開始可能"
   elif [[ ${#ddd_violations[@]} -eq 0 ]]; then
       review_status="CONDITIONAL_APPROVAL"
       status_icon="⚠️"
       next_action="軽微な改善後にTDD実装可能"
   else
       review_status="REJECTED"
       status_icon="❌"
       next_action="設計修正が必要"
   fi
   
   # Create review report
   cat > "$review_report" << EOF
# ドメイン設計レビューレポート
   
**Issues**: $(printf '#%s ' "${issue_numbers[@]}")  
**レビュー日時**: $(date)  
**ステータス**: $status_icon $review_status  
   
## 設計分析結果
   
- **エンティティ**: ${total_entities}個
- **値オブジェクト**: ${total_value_objects}個  
- **集約**: ${total_aggregates}個
   
## DDD準拠性評価
   
$(if [[ ${#ddd_violations[@]} -eq 0 ]]; then
    echo "✅ **DDD原則準拠**: 全ての基本原則が適切に適用されています"
else
    echo "❌ **DDD違反検出**: 以下の問題が発見されました"
    printf '- %s\n' "${ddd_violations[@]}"
fi)
   
## 統合性評価
   
$(if [[ ${#integration_issues[@]} -eq 0 ]]; then
    echo "✅ **統合性良好**: 既存ドメインとの整合性が保たれています"
else
    echo "⚠️ **統合課題**: 以下の改善が推奨されます"
    printf '- %s\n' "${integration_issues[@]}"
fi)
   
## 推奨アクション
   
**次のステップ**: $next_action
   
$(if [[ "$review_status" == "REJECTED" ]]; then
    echo "### 必要な修正"
    echo "1. DDD違反の修正"
    printf '   - %s\n' "${ddd_violations[@]}"
    echo "2. 設計の再検討と更新"
    echo "3. レビューの再実行"
fi)
   
$(if [[ ${#ddd_warnings[@]} -gt 0 ]]; then
    echo "### 改善推奨事項"
    printf '- %s\n' "${ddd_warnings[@]}"
fi)
EOF
   
   echo "✅ レビューレポート作成完了: $review_report"
   ```

7. **Update Metadata and Provide Decision**:
   ```bash
   # 🔄 Update metadata with review results
   echo "🔄 メタデータ更新中..."
   
   for issue_num in "${issue_numbers[@]}"; do
       metadata_file=$(find docs/use_cases -name "issue-${issue_num}-*.json" | head -1)
       if [[ -f "$metadata_file" ]]; then
           # Update review status in metadata
           update_metadata_atomic "$metadata_file" \
               --set ".phases.domain_design_review.reviewed = true" \
               --set ".phases.domain_design_review.review_status = \"$review_status\"" \
               --set ".phases.domain_design_review.review_date = \"$(date -Iseconds)\"" \
               --set ".phases.domain_design_review.review_report = \"$review_report\""
       fi
   done
   
   # Provide final decision and next steps
   echo ""
   echo "$status_icon 設計レビュー結果: $review_status"
   
   case "$review_status" in
       "APPROVED")
           echo "✅ 設計承認: TDD実装開始可能"
           echo "💡 次のステップ: /create-tests ${issue_numbers[*]}"
           ;;
       "CONDITIONAL_APPROVAL")
           echo "⚠️ 条件付き承認: 軽微な改善推奨"
           echo "💡 次のステップ: 改善適用後に /create-tests ${issue_numbers[*]}"
           ;;
       "REJECTED")
           echo "❌ 設計修正が必要です"
           echo "💡 次のステップ: /domain-modeling ${issue_numbers[*]} (再設計)"
           echo ""
           echo "主な修正事項:"
           printf '  - %s\n' "${ddd_violations[@]}"
           exit 1
           ;;
   esac
   
   echo "🎉 ドメイン設計レビュー完了!"
   ```
