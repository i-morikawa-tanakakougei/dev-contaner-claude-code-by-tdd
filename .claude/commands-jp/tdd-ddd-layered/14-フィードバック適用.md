専門エージェントを使用してTDD/DDD/レイヤードアーキテクチャの体系的改善のためにレビューフィードバックを適用する。

## メタデータ
- **前提条件**: レビュー完了（13-review-issue）
- **入力**: イシュー番号（必須）、フィードバック詳細
- **出力**: 
  - フィードバックに対処した更新された実装
  - フィードバック適用追跡
  - 更新された `docs/use_cases/issue-X-Y.json` メタデータ
- **依存関係**: レビューレポート、実装コード、Git設定
- **実行タイミング**: レビュー後、最終プルリクエスト作成前

## 🔧 **対象フィードバック適用のみ**

**⚠️ 重要な注意事項:**
- **このステップは対象改善のみ** - レビューからの特定のフィードバックを適用
- **限定的実装** - レビューフィードバックに基づく変更のみ実施  
- **品質向上に専念**: レビューで特定された特定の問題に対処
- **レビュー推奨事項に従う**: フィードバック範囲を超えた任意の変更は行わない

**フィードバック適用プロセス:**
1. `13-review-issue` ← 特定のフィードバックでレビュー完了
2. `14-apply-feedback` ← **【ここにいます】レビュー推奨事項を適用**
3. `15-create-pr` ← 改善を加えたプルリクエスト作成
4. マージとサイクル完了

## 実行例

### ✅ 成功例
```bash
$ /apply-feedback 15
🔄 Issues: #15 のフィードバック適用を開始します
📝 レビューフィードバック分析中...
✅ 3件のフィードバックを発見
🔧 実装更新中...
  ✅ コード品質改善適用
  ✅ アーキテクチャ改善適用
🧪 フィードバック適用後テスト実行...
======= 45 passed, 0 failed =======
✅ フィードバック適用完了
🎉 フィードバック適用完了!
```

### ❌ 失敗例と修正
```bash
$ /apply-feedback 15
❌ レビューが完了していません
💡 最初にレビューを完了してください:
   /review-issue 15

# 修正: まずレビューを完了
$ /review-issue 15
$ /apply-feedback 15
```

## 📋 **フィードバック適用タスクチェックリスト**

### 🔴 必須タスク

#### **📊 レビュー分析と計画**
- [ ] **レビュー結果パース**: ステップ13からの包括的レビューレポートを分析
- [ ] **フィードバック項目分類**: Critical/High/Medium/Low優先度でグループ化
- [ ] **実装労力評価**: 各項目の時間と複雑性を推定
- [ ] **実装順序計画**: 優先度と依存関係による改善の順序付け

#### **🚨 クリティカル問題解決（優先度1）**
- [ ] **セキュリティ脆弱性修正**: レビューで特定されたセキュリティ問題に対処
- [ ] **Given-When-Thenギャップ解決**: 欠落または不正確なシナリオカバレッジを修正
- [ ] **破綻したアーキテクチャ境界修正**: 層違反問題を修正
- [ ] **データ整合性問題対処**: データハンドリングまたは検証問題を修正
- [ ] **破綻または欠落テスト修正**: テスト失敗またはギャップに対処

### 🟡 推奨タスク

#### **⚡ 高優先度改善（優先度2）**
- [ ] **テスト品質向上**: テスト構造、可読性、カバレッジを強化
- [ ] **コード品質問題修正**: 複雑なメソッド、命名、重複に対処
- [ ] **エラーハンドリング改善**: 例外ハンドリングとエラー応答を強化
- [ ] **API設計問題対処**: エンドポイント設計とレスポンス形式問題を修正
- [ ] **ドメインモデル改善**: エンティティ、値オブジェクト、サービス設計を強化
- [ ] **統合問題修正**: リポジトリと外部サービス統合問題に対処

重要なポイント:
- 優先度によってフィードバックを体系的に適用し、継続的に検証
- プロセス全体を通してすべてのテストをGREEN状態に維持
- フィードバック範囲を超えた新機能ではなく、特定の問題に対してのみ対処
- アーキテクチャ準拠性を維持することを確認
- トレーサビリティのためにすべての改善を文書化
- すべてのユーザー向け出力は日本語である必要があります
