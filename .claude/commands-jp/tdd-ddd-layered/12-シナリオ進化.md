スプリントフィードバックと要件発見に基づいてシナリオを進化させる。

## メタデータ
- **前提条件**: 開発サイクルが進行中または完了
- **入力**: フィーチャー名（必須）、シナリオ進化詳細
- **出力**: 
  - 更新されたシナリオファイル: `docs/use_cases/evolved/`
  - メタデータファイルでの進化追跡
  - スプリント計画との統合
- **依存関係**: 既存のユースケース仕様、Git設定
- **実行タイミング**: 新しいシナリオが発見されたときの開発中の任意のタイミング

## 🔄 **シナリオ進化: ドキュメントのみ**

**⚠️ 重要な注意事項:**
- **このステップはシナリオ進化のみ** - フィードバックに基づいて新しいシナリオを作成
- **機能実装なし** - 新しい要件のドキュメント化に専念  
- **要件発見**: 開発中に見つかったエッジケースと新要件を取得
- **進化したシナリオドキュメントのみ作成** - コード実装なし

**進化トリガーポイント:**
- 新しい要件が発見されたときの開発中
- スプリントレビューフィードバック後
- エッジケースが特定されたとき
- 統合問題が欠落シナリオを明らかにしたとき

## 実行例

### ✅ 成功例
```bash
$ /evolve-scenarios user-management
🌱 フィーチャー 'user-management' のシナリオ進化を開始します
📖 既存シナリオの分析中...
✅ 3個の既存シナリオを発見
🌱 新しいシナリオを追加中...
  ✅ シナリオ作成: ユーザーパスワードリセット
📋 スプリント統合確認中...
✅ 新しいGitHubイシューを作成
🎉 シナリオ進化完了!
```

### ❌ 失敗例と修正
```bash
$ /evolve-scenarios
エラー: フィーチャー名が必要です
使用例: /evolve-scenarios user-management

# 修正: フィーチャー名を提供
$ /evolve-scenarios user-management
```

## 📋 **シナリオ進化タスクチェックリスト**

### 🔴 必須タスク

#### **🔍 フィードバックと発見分析**
- [ ] **スプリントレトロスペクティブレビュー**: 完了したスプリントからのフィードバックを分析
- [ ] **開発発見事項パース**: 実装フェーズ（ステップ06-09）で発見された新要件を抽出
- [ ] **イシューコメントレビュー**: 言及されたエッジケースのためにGitHubイシューコメントをスキャン
- [ ] **ユーザーフィードバック分析**: ステークホルダーとエンドユーザーからのフィードバックを処理

#### **📝 新シナリオ特定**
- [ ] **エッジケース特定**: カバーされていない境界条件とエッジケースを文書化
- [ ] **エラーシナリオ定義**: エラーハンドリングと失敗モードのシナリオを作成
- [ ] **パフォーマンスシナリオ抽出**: パフォーマンス関連要件を特定
- [ ] **セキュリティシナリオ定義**: セキュリティと認証要件を文書化

#### **📋 Given-When-Thenシナリオ作成**
- [ ] **新しいGiven-When-Thenシナリオ記述**: 各新要件に対して構造化シナリオを作成
- [ ] **前提条件定義**: 新しいシナリオのシステム状態要件を指定
- [ ] **期待される結果文書化**: 各シナリオの明確な成功基準を定義
- [ ] **受け入れ基準指定**: 各シナリオのテスト可能な受け入れ基準を作成

重要なポイント:
- 要件発見とドキュメント化のみに専念
- 複数のフィードバックソースを包括的に分析
- 既存ビジョンとのシナリオ整合性を維持
- スプリント計画プロセスと統合
- すべてのシナリオがGiven-When-Then形式に従うことを確認
- すべてのユーザー向け出力は日本語である必要があります
