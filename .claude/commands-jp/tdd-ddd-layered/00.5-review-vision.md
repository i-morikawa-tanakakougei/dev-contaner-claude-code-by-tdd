大規模プロジェクトのプロジェクトビジョンをレビューし、ステークホルダーの整合性を検証します。

## メタデータ
- **前提条件**: プロジェクトビジョンドキュメントの作成済み（00-create-vision）
- **入力**: なし（既存のビジョンドキュメントで動作）
- **出力**: 
  - ステークホルダーフィードバック付きビジョンレビューレポート
  - 整合性評価と推奨事項
  - レビューステータス付き更新済みビジョンドキュメント
  - ステークホルダー承認または必要な修正
- **依存関係**: ビジョンドキュメント、ステークホルダーアクセス、コミュニケーションツール
- **実行タイミング**: ビジョン作成後、プロジェクト構造初期化前

## 🔍 **ビジョンレビュー: 分析と整合性のみ**

**⚠️ 重要な注意:**
- **このステップはビジョンレビューのみ** - ステークホルダーとのビジョン整合性を分析・検証
- **ビジョン変更は行わない** - 評価とステークホルダーフィードバック収集に焦点  
- **整合性分析** - ビジョンの明確性、ステークホルダーの理解、ビジネス目標をレビュー
- **レビューレポートのみ生成** - ビジョンドキュメントの修正は行わない

**レビュープロセス:**
1. `00-create-vision` ← プロジェクトビジョンとコアシナリオの作成
2. `00.5-review-vision` ← **【ここにいます】ビジョン検証とステークホルダー整合性**
3. `01-init-project-structure` ← プロジェクト構造セットアップ開始（承認された場合）
4. 代替: `00-create-vision`に戻る ← ビジョン修正（整合性問題が発見された場合）

**重要なビジョン検証フォーカス:**
- ✅ プロジェクト目標に対するステークホルダーの理解と合意
- ✅ ビジネス価値整合性とROIの明確性
- ✅ スコープと制約の検証
- ✅ 成功基準と受け入れ定義

## 🎯 **大規模プロジェクト特有の考慮事項**

**このレビューを使用する場合:**
- **複数のステークホルダー**が関与（3人以上の意思決定者）
- **部門横断チーム**の整合性が必要
- **重要な予算またはタイムライン**へのコミット
- **規制またはコンプライアンス**要件
- **他チーム/システムへの外部依存関係**
- **顧客向けまたは収益重要**プロジェクト

**ステークホルダーカテゴリ:**
- **ビジネスステークホルダー**（プロダクトオーナー、経営陣）
- **技術ステークホルダー**（アーキテクト、リード開発者）
- **エンドユーザー**（顧客代表、ユーザーエクスペリエンス）
- **運用**（インフラ、サポート、保守）
- **コンプライアンス**（法務、セキュリティ、規制）

## よくあるエラーと解決策

### ❌ エラーケース1: ビジョンドキュメントが見つからない
**原因**: ビジョン作成前にビジョンレビューを実行  
**解決策**: 
```bash
# 最初にプロジェクトビジョンを作成
/create-vision
# その後レビューを実行
/review-vision
```

### ❌ エラーケース2: ステークホルダーの不整合が検出
**原因**: 異なるステークホルダーがプロジェクト目標について相反する理解を持っている  
**解決策**: 
- 全ステークホルダーとの整合セッションを促進
- 競合する要件と優先度を明確化
- 整合ギャップに対処するためビジョンドキュメントを更新
- 合意確認のためビジョンレビューを再実行

### ❌ エラーケース3: スコープクリープまたは不明確な境界
**原因**: ビジョンに明確なスコープ定義または成功基準が不足  
**解決策**: 
- 明示的なプロジェクト境界と制約を定義
- 明確な成功メトリクスと受け入れ基準を確立
- 明示的にスコープ外のものを文書化
- すべてのステークホルダーがスコープ制限に合意することを確実にする

   missing_docs=()

   # コアビジョンドキュメントをチェック

       fi

   # コアユースケースをチェック

   # 不足ドキュメントをチェック
   if [[ ${#missing_docs[@]} -gt 0 ]]; then

3. **ビジネス整合性分析**:
   ```bash
   # 📊 ビジネス整合性と明確性を分析
   echo "📊 ステークホルダー整合性確認中..."
   
   alignment_issues=()
   alignment_warnings=()
   
   # ビジネス目標明確性をチェック
   vision_file="docs/vision/project-vision.md"
   if grep -q "目標\|目的\|objective\|goal" "$vision_file" 2>/dev/null; then
       echo "  ✅ ビジネス目標: 明確に定義済み"
   else
       alignment_issues+=("ビジネス目標の定義が不明確")
   fi
   
   # 成功基準をチェック
   if grep -q "成功基準\|成功指標\|success criteria\|KPI\|メトリクス" "$vision_file" 2>/dev/null; then
       # 基準が測定可能かチェック
       if grep -qE "[0-9]+%|[0-9]+件|[0-9]+秒|[0-9]+円" "$vision_file" 2>/dev/null; then
           echo "  ✅ 成功基準: 測定可能な指標設定"
       else
           alignment_warnings+=("成功基準の定量化が不十分")
       fi
   else
       alignment_issues+=("成功基準が定義されていません")
   fi
   
   # スコープ境界をチェック
   if grep -q "スコープ\|範囲\|境界\|scope\|boundary" "$vision_file" 2>/dev/null; then
       echo "  ✅ スコープ境界: 適切に制限"
   else
       alignment_warnings+=("プロジェクトスコープの明確化が必要")
   fi
   
   # 制約をチェック
   if grep -q "制約\|限界\|constraint\|limitation" "$vision_file" 2>/dev/null; then
       echo "  ✅ 制約条件: 現実的な設定"
   else
       alignment_warnings+=("制約条件の明記が推奨")
   fi
   
   # 価値提案をチェック
   if grep -q "価値\|メリット\|benefit\|value" "$vision_file" 2>/dev/null; then
       echo "  ✅ 価値提案: 定義済み"
   else
       alignment_issues+=("価値提案が不明確")
   fi
   
   # 整合性ステータスをレポート
   if [[ ${#alignment_issues[@]} -eq 0 ]]; then
       echo "  ✅ ビジネス整合性: 良好"
   else
       echo "  ❌ 整合性問題が検出されました:"
       printf '    ⚠️ %s\n' "${alignment_issues[@]}"
   fi
   
   if [[ ${#alignment_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ 整合性改善推奨事項:"
       printf '    💡 %s\n' "${alignment_warnings[@]}"
   fi
   ```

           else

           fi
           
           # シナリオ品質を検証（大まかなヒューリスティック）
           detailed_scenarios=$(grep -c "Given:\|When:\|Then:" "$core_scenarios_file" 2>/dev/null || echo "0")
           if [[ $detailed_scenarios -gt 0 ]]; then
               echo "  ✅ シナリオ詳細度: 適切"
           else
               scenario_warnings+=("シナリオの詳細化が推奨")
           fi
       else
           scenario_issues+=("コアシナリオが定義されていません")
       fi
   else
       scenario_issues+=("コアシナリオファイルが見つかりません")
   fi
   
   # シナリオ検証ステータスをレポート
   if [[ ${#scenario_issues[@]} -eq 0 ]]; then
       echo "  ✅ コアシナリオ: 妥当"
   else
       echo "  ❌ シナリオ問題が検出されました:"
       printf '    ⚠️ %s\n' "${scenario_issues[@]}"
   fi
   
   if [[ ${#scenario_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ シナリオ改善推奨事項:"
       printf '    💡 %s\n' "${scenario_warnings[@]}"
   fi

   stakeholder_issues=()
   stakeholder_warnings=()

   stakeholder_info_found=false
   for file in "${vision_files[@]}"; do
       if grep -q "ステークホルダー\|stakeholder\|関係者" "$file" 2>/dev/null; then

   if [[ "$stakeholder_info_found" == true ]]; then
       echo "  ✅ ステークホルダー: 文書化済み"

       stakeholder_types=("ビジネス" "技術" "ユーザー" "運用")

           if grep -q "$type" "${vision_files[@]}" 2>/dev/null; then
               covered_types=$((covered_types + 1))
           fi
       done
       
       if [[ $covered_types -ge 3 ]]; then
           echo "  ✅ ステークホルダータイプ: ${covered_types}/4 カバー済み"

       stakeholder_warnings+=("ステークホルダー情報の文書化が推奨")
   fi
   
   # 承認/サインオフの言及をチェック
   if grep -q "承認\|approval\|合意\|agreement" "${vision_files[@]}" 2>/dev/null; then
       echo "  ✅ 承認プロセス: 定義済み"
   else
       stakeholder_warnings+=("承認プロセスの定義が推奨")
   fi
   
   # ステークホルダー分析をレポート
   if [[ ${#stakeholder_issues[@]} -eq 0 ]]; then
       echo "  ✅ ステークホルダー整合性: 良好"
   else
       echo "  ❌ ステークホルダー問題が検出されました:"
       printf '    ⚠️ %s\n' "${stakeholder_issues[@]}"
   fi
   
   if [[ ${#stakeholder_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ ステークホルダー改善推奨事項:"

   fi
