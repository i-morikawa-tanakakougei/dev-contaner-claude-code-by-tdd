スプリント計画の決定を実行前にレビューし、GitHub Issue作成戦略を検証する

## メタデータ
- **前提条件**: スプリント計画文書が作成されている（02-sprint-planning）
- **入力**: スプリント番号（必須）、追加オプション（オプション）
- **出力**: 
  - スプリント計画レビューレポート
  - Issue作成戦略の検証
  - レビュー結果で更新されたスプリント計画
  - 承認または必要な修正
- **依存関係**: スプリント計画文書、GitHub設定、プロジェクトビジョン
- **実行タイミング**: スプリント計画後、ユースケース仕様前

## 🔍 **スプリント計画レビュー: 分析のみ**

**⚠️ 重要な注意:**
- **このステップはスプリントレビューのみ** - スプリント計画品質の分析と評価
- **実行や変更なし** - 評価と検証に集中  
- **品質分析** - シナリオ優先順位付け、容量計画、Issue戦略のレビュー
- **レビューレポートのみ生成** - スプリント計画の修正なし

**レビュープロセス:**
1. `02-sprint-planning` ← スプリント計画とバックログが作成された
2. `02.5-review-sprint-plan` ← **【現在位置】スプリント計画品質レビュー**
3. `03-create-use-case` ← ユースケース仕様開始（承認の場合）
4. 代替: `02-sprint-planning`に戻る ← スプリント再計画（重大な問題が見つかった場合）

**重要なスプリント検証焦点:**
- ✅ コアシナリオの整合性と優先順位付け
- ✅ スプリント容量と工数見積もりの精度
- ✅ GitHub Issue作成戦略の適切性
- ✅ 依存関係の特定と管理

## よくあるエラーと解決策

### ❌ エラーケース1: スプリント計画文書が見つからない
**原因**: スプリント計画完了前にスプリントレビューを試行  
**解決策**: 
```bash
# まずスプリント計画を作成
/sprint-planning <sprint-number>
# その後レビューを実行
/review-sprint-plan <sprint-number>
```

### ❌ エラーケース2: コアシナリオとの不整合
**原因**: スプリントシナリオがプロジェクトビジョンとコアシナリオと整合しない  
**解決策**: 
- docs/use_cases/core/index.mdのコアシナリオをレビュー
- スプリント計画をプロジェクト優先順位と再整合
- コアビジネス価値に焦点を当てるようスプリント計画を更新

### ❌ エラーケース3: 容量オーバーコミット
**原因**: スプリント計画にチーム容量に対して多すぎるシナリオが含まれている  
**解決策**: 
- スプリントスコープを現実的な容量に削減
- 高価値のコアシナリオを優先
- 低優先度項目を将来のスプリントに移動

3. **コアシナリオ整合性分析**:
   ```bash
   # 📊 コアシナリオ整合性を分析
   echo "📊 コアシナリオ整合性確認中..."
   
   alignment_issues=()
   alignment_warnings=()
   
   # コアシナリオが存在するかチェック
   core_scenarios_file="docs/use_cases/core/index.md"
   if [[ ! -f "$core_scenarios_file" ]]; then
       alignment_issues+=("コアシナリオファイルが見つかりません: $core_scenarios_file")
   else
       # スプリント計画からシナリオを抽出
       sprint_scenarios=$(grep -c "^- \[.*\]" "$sprint_plan" 2>/dev/null || echo "0")
       
       # コアシナリオを抽出
       core_scenarios=$(grep -c "^- \*\*" "$core_scenarios_file" 2>/dev/null || echo "0")
       
       if [[ $core_scenarios -gt 0 ]]; then
           # カバレッジパーセンテージを計算（簡略ヒューリスティック）
           coverage_percent=$(( (sprint_scenarios * 100) / core_scenarios ))
           echo "  📊 選択シナリオ: ${sprint_scenarios}個 (コアシナリオの${coverage_percent}%をカバー)"
           
           if [[ $coverage_percent -ge 60 && $coverage_percent -le 90 ]]; then
               echo "  ✅ 優先順位付け: 適切"
           elif [[ $coverage_percent -gt 90 ]]; then
               alignment_warnings+=("スプリントスコープが大きすぎる可能性: ${coverage_percent}%")
           else
               alignment_issues+=("コアシナリオカバレッジが不十分: ${coverage_percent}%")
           fi
       else
           alignment_warnings+=("コアシナリオが特定できません")
       fi
   fi
   
   # ビジネス価値焦点をチェック
   if grep -q "ビジネス価値\|business value\|優先度" "$sprint_plan" 2>/dev/null; then
       echo "  ✅ ビジネス価値: 考慮済み"
   else
       alignment_warnings+=("ビジネス価値の明記不足")
   fi
   
   # 整合性ステータスをレポート
   if [[ ${#alignment_issues[@]} -eq 0 ]]; then
       echo "  ✅ コアシナリオ整合性: 良好"
   else
       echo "  ❌ 整合性問題が検出されました:"
       printf '    ⚠️ %s\n' "${alignment_issues[@]}"
   fi
   
   if [[ ${#alignment_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ 整合性改善推奨事項:"
       printf '    💡 %s\n' "${alignment_warnings[@]}"
   fi
   ```

4. **容量と工数分析**:
   ```bash
   # 📈 容量計画を分析
   echo "📈 容量計画分析中..."
   
   capacity_issues=()
   capacity_warnings=()
   
   # スプリント計画から工数見積もりを抽出
   total_effort=$(grep -E "[0-9]+SP|[0-9]+\s*ストーリーポイント" "$sprint_plan" 2>/dev/null | \
                 sed -E 's/.*([0-9]+)SP.*/\1/; s/.*([0-9]+)\s*ストーリーポイント.*/\1/' | \
                 awk '{sum += $1} END {print sum}')
   
   # チーム容量を抽出（文書化されている場合）
   team_capacity=$(grep -E "容量|capacity|キャパシティ" "$sprint_plan" 2>/dev/null | \
                  grep -oE "[0-9]+" | head -1)
   
   if [[ -n "$total_effort" && "$total_effort" != "0" ]]; then
       echo "  📊 見積もり工数: 合計${total_effort}SP"
       
       if [[ -n "$team_capacity" && "$team_capacity" != "0" ]]; then
           echo "  📊 チーム容量: ${team_capacity}SP"
           
           # 利用率を計算
           utilization=$(( (total_effort * 100) / team_capacity ))
           buffer=$(( 100 - utilization ))
           
           echo "  📊 バッファ: ${buffer}%"
           
           if [[ $utilization -le 80 ]]; then
               echo "  ✅ 容量計画: 適切 (${utilization}%利用)"
           elif [[ $utilization -le 90 ]]; then
               capacity_warnings+=("容量利用率が高め: ${utilization}%")
           else
               capacity_issues+=("容量オーバーコミット: ${utilization}%利用")
           fi
       else
           capacity_warnings+=("チーム容量が明記されていません")
       fi
   else
       capacity_warnings+=("工数見積もりが見つかりません")
   fi
   
   # 工数見積もり品質をチェック
   if grep -q "見積もり根拠\|estimation rationale" "$sprint_plan" 2>/dev/null; then
       echo "  ✅ 見積もり根拠: 記載済み"
   else
       capacity_warnings+=("見積もり根拠の記載不足")
   fi
   
   # 容量ステータスをレポート
   if [[ ${#capacity_issues[@]} -eq 0 ]]; then
       echo "  ✅ 容量計画: 適切"
   else
       echo "  ❌ 容量計画問題が検出されました:"
       printf '    ⚠️ %s\n' "${capacity_issues[@]}"
   fi
   
   if [[ ${#capacity_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ 容量計画改善推奨事項:"
       printf '    💡 %s\n' "${capacity_warnings[@]}"
   fi
   ```

   ```bash
   issue_strategy_problems=()
   issue_strategy_warnings=()
   
   # バックログが存在し適切な構造を持っているかチェック
   if [[ -f "$sprint_backlog" ]]; then
       # 計画済みIssueをカウント
       planned_issues=$(grep -c "^## Issue" "$sprint_backlog" 2>/dev/null || echo "0")
       
       if [[ $planned_issues -gt 0 ]]; then
           echo "  📊 計画済みIssue数: ${planned_issues}個"
           
           # 受け入れ基準でGiven-When-Thenをチェック
           gwt_coverage=$(grep -c "Given:\|When:\|Then:" "$sprint_backlog" 2>/dev/null || echo "0")
           
           if [[ $gwt_coverage -gt 0 ]]; then
               echo "  ✅ 受け入れ基準: Given-When-Then完全記載"
           else
               issue_strategy_problems+=("Given-When-Then受け入れ基準が不足")
           fi
           
           # Issue構造の一貫性をチェック
           issue_titles=$(grep "^## Issue" "$sprint_backlog" | wc -l)
           acceptance_criteria=$(grep -c "受け入れ基準\|Acceptance Criteria" "$sprint_backlog" || echo "0")
           
           if [[ $acceptance_criteria -eq $issue_titles ]]; then
               echo "  ✅ Issue構造: 1シナリオ=1Issue戦略適用"
           else
               issue_strategy_warnings+=("Issue構造の一貫性改善推奨")
           fi
       else
           issue_strategy_problems+=("計画済みIssueが見つかりません")
       fi
   else
       issue_strategy_problems+=("スプリントバックログが見つかりません")
   fi
   
   # GitHub CLI準備状況をチェック
   if command -v gh >/dev/null 2>&1; then
       if gh auth status >/dev/null 2>&1; then
           echo "  ✅ GitHub CLI: 認証済み"
       else
           issue_strategy_warnings+=("GitHub CLI認証が必要")
       fi
   else
       issue_strategy_warnings+=("GitHub CLIのインストールが必要")
   fi
   
   # Issue戦略ステータスをレポート
   if [[ ${#issue_strategy_problems[@]} -eq 0 ]]; then
       echo "  ✅ Issue戦略: 適切"
   else
       echo "  ❌ Issue戦略問題が検出されました:"
       printf '    ⚠️ %s\n' "${issue_strategy_problems[@]}"
   fi
   
   if [[ ${#issue_strategy_warnings[@]} -gt 0 ]]; then
       echo "  ⚠️ Issue戦略改善推奨事項:"
       printf '    💡 %s\n' "${issue_strategy_warnings[@]}"
   fi
   ```
