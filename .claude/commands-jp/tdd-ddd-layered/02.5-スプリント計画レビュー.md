- **出力**: 
  - スプリント計画レビューレポート
  - イシュー作成戦略検証
  - レビュー結果付き更新スプリント計画
  - 承認または修正要求
- **依存関係**: スプリント計画文書、GitHub設定、プロジェクトビジョン
- **実行タイミング**: スプリント計画後、ユースケース仕様前

## 🔍 **スプリント計画レビュー: 分析のみ**

**⚠️ 重要な注意事項:**
- **このステップはスプリントレビューのみ** - スプリント計画品質を分析・評価
- **実行や変更なし** - 評価と検証に専念  
- **品質分析** - シナリオ優先順位付け、容量計画、イシュー戦略をレビュー
- **レビューレポートのみ生成** - スプリント計画の修正は行わない

**レビュープロセス:**
1. `02-sprint-planning` ← スプリント計画とバックログ作成
2. `02.5-review-sprint-plan` ← **【ここにいます】スプリント計画品質レビュー**
3. `03-create-use-case` ← ユースケース仕様開始（承認時）
4. 代替: `02-sprint-planning` に戻る ← スプリント再計画（重大問題発見時）

**重要スプリント検証焦点:**
- ✅ コアシナリオ整合性と優先順位付け
- ✅ スプリント容量と工数見積もり精度
- ✅ GitHubイシュー作成戦略の適切性
- ✅ 依存関係の特定と管理

## よくあるエラーと解決策

### ❌ エラーケース1: スプリント計画文書が見つからない
**原因**: スプリント計画完了前にスプリントレビューを実行  
**解決策**: 
```bash
# まずスプリント計画を作成
/sprint-planning <sprint-number>
# その後レビュー
/review-sprint-plan <sprint-number>
```

### ❌ エラーケース2: コアシナリオとの整合性不良
**原因**: スプリントシナリオがプロジェクトビジョンとコアシナリオに整合しない  
**解決策**: 
- docs/use_cases/core/index.md でコアシナリオを確認
- プロジェクト優先順位でスプリント計画を再整合
- コアビジネス価値に焦点を当てるよう計画を更新

### ❌ エラーケース3: 容量オーバーコミット
**原因**: スプリント計画にチーム容量を超える多くのシナリオが含まれる  
**解決策**: 
- 現実的な容量までスプリントスコープを削減
- 高価値コアシナリオを優先
- 低優先度項目を将来のスプリントに移動
